# Grammar based fuzzing

Fuzzes daslang by generating syntactically valid programs from its own Bison
grammar, so inputs get past the parser and stress type checking, AOT codegen
and the JIT instead of dying at the first token.

## Quick start

```
git submodule update --init --recursive
./setup.sh
./launch20_supervised.sh
```

`setup.sh` is idempotent — it only does what is missing, so it is safe to
re-run after a pull. `--force` rebuilds everything.

It checks prerequisites, generates the grammar, builds the mutator and the
instrumented target, and writes seeds. Prerequisites it cannot install for you:

```
sudo apt install cmake ninja-build python3 default-jre make clang libclang-dev llvm-dev
git clone https://github.com/AFLplusplus/AFLplusplus ~/work/AFLplusplus
make -C ~/work/AFLplusplus -j$(nproc)
```

Point elsewhere with `AFL_DIR=/path/to/AFLplusplus ./setup.sh`.

If `afl-fuzz` refuses to start, complaining about `core_pattern`:

```
echo core | sudo tee /proc/sys/kernel/core_pattern
```

## The generated grammar is not in git

`type_inference_simple.json` is derived from
`modules/daScript/src/parser/ds2_parser.ypp` and is regenerated by `setup.sh`.
Checking it in only guarantees it drifts from the submodule it came from.

Regenerating it by hand is **two steps** — this trips people up:

```
python3 convert.py modules/daScript/src/parser/ds2_parser.ypp > type_inference_simple.json
python3 convert.py --apply type_inference_simple.json
```

The first pass converts the Bison grammar. The second applies `START_PROLOGUE`,
`UNIT_TEST_RULES`, `REPLACE_RULES` and `BIAS`. **Skip `--apply` and `<START>`
comes out as a bare `<program>`** — no `require UnitTest` prologue, no weighting,
and the generated programs are far weaker.

After changing the grammar you must also force the mutator to regenerate: its
Makefile depends on `.grammar` (a path file), not on the JSON contents, so
editing the JSON alone triggers no rebuild.

```
rm -f modules/Grammar-Mutator/src/f1_c_fuzz.c modules/Grammar-Mutator/include/f1_c_fuzz.h
make -C modules/Grammar-Mutator GRAMMAR_FILE=$PWD/type_inference_simple.json -j$(nproc)
```

`setup.sh --force` does both.

### Validating a grammar change

Three things must hold, or the mutator will not build or will emit garbage:

- no undefined non-terminals
- no unproductive symbols (a rule that can never terminate)
- no cycle in Grammar-Mutator's *cheap grammar* — its `f1_c_gen.py` recurses
  through minimum-cost rules, so a zero-cost terminal that ties for minimum in
  a self-recursive rule gives `RecursionError` and the generator never builds

`setup.sh` checks the first two. The third is worth checking by hand for any
change that adds a literal which could be empty.

## Running

`launch20_supervised.sh` starts 20 instances in a tmux session named `fuzz`
(1 main + 19 secondaries with varied power schedules), each under a restart
loop. Override with `N=8 ./launch20_supervised.sh`.

```
tmux attach -t fuzz                       # watch
~/work/AFLplusplus/afl-whatsup out_clean  # aggregate status
tmux kill-session -t fuzz                 # stop
```

Two things the supervision exists for:

- **`AFL_NO_AFFINITY` is set deliberately.** AFL pins each instance to a free
  core; a restarting instance finds its siblings holding every core, aborts
  with `No more free CPU cores`, and the restart loop spins.
- **Orphaned children are reaped before each restart.** When `afl-fuzz` dies —
  OOM, or the null-deref in `libgrammarmutator-type.so`, which runs in-process
  and takes the fuzzer down with it — its `das_fuzz` children are never
  reaped. They accumulate at ~0.4 GB each; 127 of them once held 27.8 GB and
  drove a 703-restart spiral.

`watchdog.sh` is a slower backstop that revives instances whose tmux window
lost its `afl-fuzz`.

Findings land in `out_clean/<instance>/crashes` and `.../hangs`. Note AFL
archives both into timestamped `crashes.<date>` directories on every restart,
so the full history is those plus the live directory.

## Triaging a crash

```
./triage_crash.sh out_clean/fuzzer03/crashes/id:000000,sig:06,...
```

Classifies against the known bug set and prints `KNOWN#n`, `SEGFAULT`,
`UNKNOWN: <error>` or `NOREPRO`. It replays through `build_plain/das_fuzz`
(a non-instrumented build reading stdin), so build that first if you have not:

```
cmake -B build_plain -GNinja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
  -DDAS_GLFW_DISABLED=ON -DDAS_TESTS_DISABLED=ON -DDAS_TUTORIAL_DISABLED=ON
cmake --build build_plain --target das_fuzz daslang -j$(nproc)
```

Useful environment variables on the target:

| variable | effect |
|---|---|
| `DAS_FUZZ_DIAG=1` | print the clang errors and the generated AOT C++ before aborting |
| `DAS_FUZZ_NO_AOT=1` | skip the AOT pass |
| `DAS_FUZZ_NO_JIT=1` | skip the JIT pass |

A crash that does not reproduce standalone is not automatically noise, but it
is usually state carried over inside the persistent loop. Always confirm
against a freshly built target: a `das_fuzz` older than the `daslib/` it loads
at runtime produces AOT C++ inconsistent with its linked library, and every
input then looks like a crash.

### Minimizing before reporting

`afl-tmin` first, then reduce by hand — tmin shrinks bytes while preserving
coverage, so its output is usually still larger than a semantic reduction
(observed: 418 → 117 bytes by tmin, then 57 by hand).

```
MS=$(AFL_DUMP_MAP_SIZE=1 ./build_afl/das_fuzz 2>&1 | tail -1)
AFL_MAP_SIZE=$MS AFL_FORKSRV_INIT_TMOUT=120000 AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1 \
  ~/work/AFLplusplus/afl-tmin -t 15000 -i crash.das -o min.das -- ./build_afl/das_fuzz
```

Both env vars are required: without `AFL_MAP_SIZE` it aborts with
`FS_ERROR_MAP_SIZE`, and the AOT driver takes seconds to start on a loaded
box, which trips the default forkserver timeout.

Only report bugs that reproduce from a plain `daslang repro.das` or
`daslang -aot repro.das out.cpp` on unmodified source. A bug that needs
`options remove_unused_symbols = false` (or `-aot-macros`, which implies
`export_all`) only appears when dead symbols are artificially kept alive, and
does not correspond to anything real code does.

## Measuring coverage

AFL's `bitmap_cvg` is map density, not code coverage — it counts edges touched
in a map sized for the whole instrumented binary. For real numbers:

```
cmake -B build_cov -GNinja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
  -DCMAKE_C_FLAGS="-fprofile-instr-generate -fcoverage-mapping" \
  -DCMAKE_CXX_FLAGS="-fprofile-instr-generate -fcoverage-mapping" \
  -DCMAKE_EXE_LINKER_FLAGS="-fprofile-instr-generate" -DDAS_GLFW_DISABLED=ON
cmake --build build_cov --target das_fuzz -j$(nproc)

ls corpus/* | xargs -P 12 -I{} sh -c \
  'LLVM_PROFILE_FILE=/tmp/prof/p%p.profraw ./build_cov/das_fuzz < {} >/dev/null 2>&1'
llvm-profdata-20 merge -sparse /tmp/prof/*.profraw -o /tmp/cov.profdata
llvm-cov-20 report ./build_cov/das_fuzz -instr-profile=/tmp/cov.profdata \
  -ignore-filename-regex='(3rdparty|/usr/)'
```

Match the `llvm-profdata` / `llvm-cov` version to the clang that built it, or
you get `raw profile version mismatch`.

Per-function output is what makes this actionable: a visitor sitting at 0%
means the grammar never emits that construct at all.

```
llvm-cov-20 report ./build_cov/das_fuzz -instr-profile=/tmp/cov.profdata \
  -show-functions -sources modules/daScript/src/ast/ast_infer_type.cpp
```

Two constructs were found dead this way — `typeinfo` (its trait name came from
`var1..var64`, so all 85 real traits were unreachable) and `debug()` (never
emitted at all). Roughly a quarter of the binary is unreachable by
construction — gen1 parser, JSON, file IO, debugger, job queue, ABI wrappers —
so exclude those before reading the percentage.

## Grammar conversion

daslang uses Bison. Thanks to https://www.chrysalide.re/ for publishing the
script that converts a Bison grammar to the JSON format Grammar-Mutator uses;
`convert.py` is that script, adapted and since extended.

Beyond the mechanical conversion it injects UnitTest C++ binding non-terminals
(types, enums, hardcoded calls), replaces rules whose default form is
unusable, and applies a weight bias. Edit `UNIT_TEST_RULES`, `REPLACE_RULES`
and `BIAS` near the top of the script.

`convert.py` parses the `.ypp` with regexes and is sensitive to upstream
grammar changes. If a regeneration produces a grammar that fails validation,
suspect it first.
